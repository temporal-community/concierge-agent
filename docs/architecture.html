Hotel ZGY · Concierge Agent · How it works

Three ways in. One durable workflow per stay.

Guests type in the browser, talk to it, or use the in-room device. Every turn becomes a Temporal Update on that guest's ConciergeStayWorkflow, which owns the conversation, the tools and the rides.

The life of one turn

  1. 1

    Ask

    The guest types in the chat or speaks. For voice, Deepgram transcribes and calls the Think endpoint through the dev tunnel, using the concierge as its LLM.

  2. 2

    Submit

    Whatever the channel, ConciergeService sends one SubmitTurn Update. The browser, the voice relay and the room device all share this path.

  3. 3

    Run

    Temporal delivers the Update to the guest's ConciergeStayWorkflow, a long-running workflow that holds the conversation, pending ride offers and memory.

  4. 4

    Think and act

    The workflow searches hotel knowledge in pgvector, calls the chat model, and runs each tool the model asks for as an activity that Temporal retries and records.

  5. 5

    Stream back

    The model activity sends partial answer text with pg_notify. Web listens and streams it into the chat, or to Deepgram to be spoken.

  6. 6

    Track rides

    Each booking runs as its own workflow in the ride service. Status changes are published to the stay's Workflow Stream, which feeds the ride Activity panel.
