Hotel ZGY · Concierge Agent · Voice

Deepgram hears and speaks. The concierge does the thinking.

The guest talks to the browser. Deepgram's Voice Agent turns speech into text and text back into speech, but its "think" step calls our own endpoint, so a spoken question runs through the same stay workflow as a typed one.

One spoken turn

  1. 1

    Speak

    The browser's mic worklet streams 16 kHz audio over a WebSocket to the voice relay. The browser never connects to Deepgram itself.

  2. 2

    Relay

    The relay opens a Voice Agent session with the server's API key, sends the settings (Flux listen model, Flux voice, our Think endpoint as the LLM) and forwards the audio.

  3. 3

    Transcribe

    When the guest finishes speaking, Deepgram calls the Think endpoint through the dev tunnel with the transcript and the voice session's bearer token.

  4. 4

    Think

    The Think endpoint submits the transcript as a SubmitTurn Update on the guest's stay workflow. It's the same path a typed question takes, so the turn also shows up in the chat.

  5. 5

    Answer

    Answer text streams back as the model writes it. The Think endpoint returns it to Deepgram as streamed chat-completion chunks, and Deepgram starts speaking.

  6. 6

    Play

    The relay paces the 24 kHz speech to the browser's speaker worklet, using the browser's playback acknowledgements so audio never runs far ahead.

When the guest talks over the concierge

  1. Deepgram hears the guest and sends UserStartedSpeaking.
  2. The relay tells the browser to silence playback right away.
  3. The browser confirms it's silent.
  4. The relay marks the cut-off turn as interrupted in the stay workflow, and the chat shows it as "Interrupted".
